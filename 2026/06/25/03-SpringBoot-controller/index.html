03_SpringBoot controller

发表于2026-06-25|更新于2026-06-25
|浏览量:

controller：

  • 接待请求：监听浏览器或前端发来的 HTTP 请求（如 http://localhost:8080/hello ）
  • 转交任务：把请求参数解析出来，交给 Service 业务层处理。
  • 返回响应：把处理结果（通常是 JSON 数据或网页）返回给客户端。

service：处理业务逻辑
dao：编写SQL，操作数据库
entity：和数据库对应，一张表对应一个实体

1. 控制层两大注解

该注解写在具体的类上：

注解 作用 使用场景
@Controller 标注该类是一个控制器，返回视图名（如跳转到 index.html） 传统 MVC 网页（后端渲染页面）
@RestController @Controller + @ResponseBody 的结合体，专门返回 JSON 数据 前后端分离项目

2. 路由映射（让前端找到你）

通过注解将 URL 映射到具体的方法上：

注解 对应 HTTP 请求方式 用途
@GetMapping("/xxx") GET 查询数据（打开页面、获取列表）
@PostMapping("/xxx") POST 新增数据（提交表单）
@PutMapping("/xxx") PUT 修改数据
@DeleteMapping("/xxx") DELETE 删除数据
@RequestMapping("/xxx") 通用匹配（可指定 method） 通用配置

浏览器地址栏发送的是GET请求

@RequestMapping注解主要负责URL的路由映射。它可以添加在Controller类或者具体的方法上。如果添加在Controller类上，则这个Controller中的所有路由映射都将会加上此映射规则，如果添加在方法上，则只对当前方法生效。

@RequestMapping注解的属性参数：

  • value：请求URL的路径，支持URL模板、正则表达式符号“*”匹配任意字符，符号 “**” 匹配任意路径，符号 “?” 匹配单个字符。
  • method： HTTP请求方法，包括RequestMethod.GET、RequestMethod.POST、RequestMethod.DELETE、RequestMethod.PUT等值

3. 参数传递

3.1 接收 URL 路径中的值（@PathVariable）

3.2 接收 URL 问号后面的参数（@RequestParam）

请求示例：http://localhost:8080/test?name=lpq&phone=123

确保函数形参和请求中的名称一致
参数不一致时，通过@RequestParam注解来设置，要设置required为false否则不传参数方法访问不到。

post请求可以通过apipost进行发送

3.3 接收 JSON 格式的请求体（@RequestBody）


User 类放在entity包中，且含有name和password属性，属性名和json中的请求数据一致。
必须含有无参构造方法。

千万不要用 @RequestBody 去接 GET 请求，会报 400 错误（GET 没有 Body）。
