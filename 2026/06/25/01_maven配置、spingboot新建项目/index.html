1. Maven配置

1.1 Maven的作用

  1. 依赖管理（“搬运” Jar 包）
    Java 项目通常需要引入大量第三方库。如果没有 Maven，你需要自己去网上下载 Jar 文件，复制进项目，还要手动处理版本冲突（比如 A 包需要 B 包的 1.0 版，但 C 包需要 B 包的 2.0 版）。
    Maven 的做法：你只需在项目根目录的 pom.xml 文件中声明需要什么（比如 spring-boot-starter-web），Maven 就会自动从中央仓库下载这些 Jar 包以及它们所依赖的其他 Jar 包，并统一存放在你电脑的本地仓库中。
  2. 项目构建（“编译打包”）
    你写的 .java 文件无法直接运行，需要先编译成 .class 文件，再打包成可执行的 .jar 或 .war 文件。
    Maven 的做法：它定义了一套标准的生命周期（Lifecycle），你只需要执行几个简单的命令：
  1. 统一开发结构
    Maven 强制规定了项目的目录结构，比如：
    src/main/java —— 放你的业务代码
    src/main/resources —— 放配置文件（如 application.properties）
    src/test/java —— 放测试代码
    target/ —— 放编译后的 class 文件和打包产物
    只要大家都遵循这个规范，别人接手你的项目时就能秒懂结构，不用额外解释。

1.2配置本地仓库

Maven 所需要的任何构件都是直接从本地仓库获取的。如果本地仓库没有，它会首先尝试从远程仓库下载构件至本地仓库。
